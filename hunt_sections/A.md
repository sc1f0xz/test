## A. Trajectory agent ที่มี reasoning จากโมเดลตระกูล Qwen (และโมเดลเปิดรูปแบบใกล้เคียง) พร้อมสัญญาณความสำเร็จ: terminal / SWE / data-science / DevOps / SQL / browser / filesystem / MCP

- **ของใหม่ที่ตรงที่สุดในรอบนี้:** มี 2 ชุด
  - [allenai/tmax-sft](https://huggingface.co/datasets/allenai/tmax-sft): ครูคือ **Qwen3.6-27B (thinking)** มี `reasoning_content` และมี split `only_success` ที่ผ่าน verifier แล้ว ใช้ license ODC-BY ไฟล์ 41 MB trajectory สั้น (18–38 messages) จึงน่าจะพอดีกับ context 16K
  - [nvidia/Open-SWE-Traces](https://huggingface.co/datasets/nvidia/Open-SWE-Traces) v1.2: ครูคือ **Qwen3.8-27B (thinking, xhigh)** ซึ่งเป็นตัวเดียวกับครูของเรา ครบ 5 harness และมี `resolved` ส่วนที่มีอยู่แล้ว (opencode / qwen38_flash_next / scale-swe) **ไม่ทับกับ** subset `qwen38_27b` ชุดนี้
- **ชุด task+verifier สำหรับให้ครู Qwen3.8-27B สร้างคำตอบใหม่:**
  - [allenai/TMax-15K](https://huggingface.co/datasets/allenai/TMax-15K): 14,601 env ครอบคลุม file_operations, data_querying (SQL), data_science, system_administration, security และอื่น ๆ (รวม 9 domain) มี pytest ทั้งสถานะเริ่มต้นและสถานะจบ พร้อม container def
  - [open-athena/task-trove](https://huggingface.co/datasets/open-athena/task-trove): 930,918 task จาก 103 แหล่ง มีแบบ Harbor ของ nl2bash, stackexchange-unix/superuser, e2egit, MiMo general (MCP)
  - [FineEnvs/data-agent-harbor-train](https://huggingface.co/datasets/FineEnvs/data-agent-harbor-train): DS 5,000 task ตรวจด้วย grader แบบ deterministic
  - [SWE-Lego/Terminal-Lego-15k](https://huggingface.co/datasets/SWE-Lego/Terminal-Lego-15k)
- **กับดักใน open-athena:**
  - trace แบบ `*-131k-opencode-traces` (ทั้งแบบปกติและแบบ literal-rescue) ที่เปิดดูแถวจริง **ข้อความ user แรกว่างเปล่า (prompt ของ task หายไป)** และยาวมาก ถ้าจะใช้ต้อง join กลับไปหา `instruction` ใน task-trove ด้วย task id
  - ส่วนชุด `*-32k-traces` (Terminus-2) มี prompt ครบและมี `<think>` ทุกเทิร์น แต่ **ทั้งตระกูลไม่มี license**
- **หมวดที่บางมาก:**
  - browser แบบข้อความ: ชุดที่เจอใช้ wiki หรือเป็นภาพหน้าจอ
  - SQL agent แบบหลายเทิร์นที่ไม่ใช่ benchmark: มีแค่ส่วน `darl/sql` ของ DataMind-12K และ domain data_querying ของ TMax-15K
  - MCP ที่ไม่ใช่ trace จาก benchmark: มีแค่ env ของ MiMo general (925 task, ตรวจด้วย rubric) ซึ่งเป็น prompt-only
  - DevOps: มีแค่ ghactions-v3 และ e2egit ของ open-athena

**ตัดออก / ลดลำดับ**
- open-athena `*-qwen3.5-122b-131k-opencode-traces` และ `*-literal-rescue-traces` (เช่น superuser 9,979, overflow 9,996, swe-rebench-patched 2,290 / 6.8 GB, r2egym 3,327 / 10.8 GB): ในแถวจริง **ข้อความ user แรกว่าง (prompt ของ task หาย)** และ trace ยาวถึง 131k ส่วนชุด superuser/overflow ให้เขียนคำตอบลง `response.txt` แล้วตรวจด้วย **LLM judge (gpt-4o-mini)** จึงไม่ใช่งาน terminal จริง ควรใช้ชุด `-32k-traces` แทน หรือ join `task` กับ task-trove
