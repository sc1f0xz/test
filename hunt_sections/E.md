## E. โจทย์ที่ตรวจคำตอบอัตโนมัติได้และยากกว่า GSM8K (คณิตแข่งขัน · โค้ด+เทสต์ · SQL รันจริง · ตาราง · regex · constraint · puzzle)

- **ชุดใหม่ที่คุ้มที่สุดคือชุดที่มี pass rate ของโมเดลขนาด 4B ติดมาด้วย** `PrimeIntellect/SYNTHETIC-2-RL` (ใหม่) มีคอลัมน์ `Qwen/Qwen3-4B_avg_reward` ครบทั้ง 155,638 แถว (ค่ามัธยฐาน 0.099 แปลว่าโจทย์ส่วนใหญ่ยากสำหรับ 4B) ใช้คู่กับ `INTELLECT-3-RL` (รอบก่อน มี avg@k ของ Qwen3-4B) เพื่อเลือกโจทย์ช่วง "ทำได้บ้าง" (0<p<1) ให้ครู Qwen3.8-27B สร้างคำตอบ และใช้ทำ budget คิดสั้น/ยาวได้ทันที ส่วน `Skywork-OR1` math มี `model_difficulty` 0–16 เทียบกับ R1-Distill 1.5B/7B/32B
- **SQL ไม่ใช่ wiki ล้วน: Spider ใช้ wiki 45%** ตรวจในเปเปอร์ Spider แล้ว (VERIFIED): DB 90 จาก 200 ตัว "created based on WikiSQL… tables in WikiSQL are from Wikipedia" จึงให้ตัด Spider-train หรือกรองตาม db_id ส่วน BIRD ไม่มี wiki (Kaggle 32% / CTU Prague 48% / สร้างเอง 20%) และ SynSQL เป็น DB สังเคราะห์ทั้งหมด ชุด SQL ที่ใช้ได้จริงและเล็กคือ `SynSQL-Complex-5K` (4,000 train) คู่กับ `databases.zip` 54.5 MB ของ SynSQL-2.5M
- **ตาราง:** Table-R1-Zero เป็น wiki 86% (WTQ 13,706 + TabFact 20,740 + FeTaQA 7,324 จาก 48,563 แถว) จึงตัดออก ตัวเลือกที่ไม่ใช่ wiki คือ TAT-QA (รายงานการเงิน 13,251 ข้อ เป็นโจทย์คำนวณ 5,553 ข้อ) และ FinQA กับ HiTab ซึ่ง HiTab มีแถวจาก ToTTo (wiki) 1,376/7,417 = 18.6% ต้องกรองด้วย `table_source != totto`
- **regex, unit conversion และ JSON schema ยังบาง:** ไม่มีชุดใหญ่คุณภาพดี regex มีแค่ชุดเล็กหลักพันข้อ unit conversion มีเพียงชุดของเล่น 1,500 ข้อ (ไม่แนะนำ) ส่วน JSON schema ที่มีอยู่แล้ว (SchemaStress / JSONSchemaBench / Structured-Outputs-v2) ครอบคลุมพอ **ข้อควรระวังใหม่:** `Nemotron-RL-Instruction-Following-Free-Form-Formatting-v1` ใช้ regex เป็นตัวตรวจก็จริง แต่ context ในแถวที่เปิดดูเป็นบทความ Wikipedia จึงต้องตัดออก ทุกชุดในหมวดนี้เป็นภาษาอังกฤษ (ไม่พบชุดไทยที่มีตัวตรวจ)
