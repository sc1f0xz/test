## L. Environment และเครื่องมือสำหรับสร้าง trajectory เอง (ประเมินจาก README อย่างเดียว ไม่ได้ติดตั้ง)

- **เรื่อง GPU ของครู:** Qwen3.8-27B แบบ bf16 ใช้หน่วยความจำราว 54 GB (27B × 2 ไบต์) จึงต้องใช้ GPU 80 GB หรือ quantize เป็น FP8 ถึงจะเหลือที่ให้ KV-cache บน GPU เดียว ทุกเครื่องมือในตารางนี้คุยกับครูผ่าน endpoint ที่เข้ากันได้กับ OpenAI (vLLM) ได้หมด ข้อจำกัดจริงจึงอยู่ที่ **Docker, ดิสก์ และ CPU ของเครื่องที่รัน environment** ไม่ใช่ GPU · ต้องเปิด tool-call parser ของ vLLM ให้ตรงกับรูปแบบของ Qwen
- **คุ้มที่สุด (ติดตั้งง่าย มีตัวตรวจในตัว ไม่ต้อง Docker):**
  - reasoning-gym สำหรับคิดสั้น/ยาว
  - tau2-bench (เฉพาะ split train ของ gym) สำหรับ tool + ผู้ใช้จำลอง
  - AppWorld (split train/dev) สำหรับเขียนโค้ดเรียก API
  - verifiers หรือ NeMo Gym สำหรับเลือก environment สำเร็จรูปจำนวนมาก
- **ฝั่ง terminal/SWE:** mini-swe-agent หรือ Harbor (terminus-2) คู่กับงานจาก SWE-smith หรือ R2E-Gym เป็นชุดที่เรียบง่ายที่สุด แต่ต้องใช้ Docker และดิสก์หลักร้อย GB (image ละ 300–500 MB ตาม README ของ R2E-Gym)
- **กฎกันปน eval:** ห้ามสร้าง trajectory บน split test หรือ benchmark ที่เราใช้วัดผล (τ²-bench test, AppWorld test_*, Terminal-Bench 2.x/3.0, SWE-bench Verified/Live, MCPMark standard, AgentDojo ถ้าจะใช้วัดความทนต่อ injection) ให้ใช้เฉพาะ split train หรืองานที่สร้างขึ้นเอง
