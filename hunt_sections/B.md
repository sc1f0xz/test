## B. Function/tool calling ที่มีเฉลย call (single / parallel / multi-turn / nested / ถามกลับ / ไม่ควรเรียก / กู้จาก error / เลือกจาก tool จำนวนมาก / schema ซับซ้อน)

- **หมวดที่มีข้อมูลเยอะและตรวจได้จริง:** single, parallel และ "ไม่ควรเรียก tool" (irrelevance) มีชุดที่มีเฉลยครบและตรวจได้ด้วยการ execute (Dria verifiable lite, Synth-APIGen, xLAM) หรือด้วย exact-match (zake7749)
- **หมวดที่บาง:** "ถามกลับเมื่อข้อมูลไม่ครบ" มีของจริงแค่ When2Call (train) กับ ToolRL rlla4k ส่วน "กู้จาก tool error" **แทบไม่มีชุดที่ใช้ได้**: ชุดเดียวที่ตั้งใจทำคือ HardGen แต่สุ่มเก็บใน environment ของ BFCL (🔴) ส่วนชุดของ rmems ห้ามใช้เทรนตามเงื่อนไขของผู้สร้าง ถ้าต้องการหมวดนี้ต้องให้ครูสร้างเอง โดยฉีด error ลงใน env ของ Dria/Synth-APIGen ที่ execute ได้
- **การปนกับ BFCL:** When2Call **ส่วน test สร้างจาก BFCL v2 Live** (ตรวจจากแถวจริงแล้ว: `source="BFCL v2 Live Multiple"`) จึงใช้ได้เฉพาะ train · HardGen/FunReason-MT ใช้ API ของ BFCL multi-turn โดยตรง (ไฟล์ชื่อ `bfcl_multi_turn.json`) · Dria แบ่งหมวด simple/parallel/multiple ตามชื่อหมวดของ BFCL (ซ้ำแค่รูปแบบ ไม่ได้ซ้ำข้อมูล) · ส่วน τ-bench/τ²-bench ไม่อยู่ในรายการต้องห้าม แต่ APIGen-MT และ AReaL-tau2 ใช้โดเมนและ DB เดียวกันกับ benchmark นี้
- **เรื่องโมเดลตระกูลเดียวกัน:** ชุดที่มี thinking จากโมเดลตระกูล Qwen มี 2 ชุด คือ zake7749 (Qwen3.6-35B-A3B, prompt เป็นชุด Nemotron Pivot ที่เรามีอยู่แล้ว แต่คำตอบสร้างใหม่) และ Nemotron-SFT-Agentic-v4 (Qwen3.5-397B) ชุดอื่นๆ เหมาะกับ "prompt + ตัวตรวจ" แล้วให้ Qwen3.8-27B สร้างคำตอบใหม่

### ตัดออก
- **Bingguang/HardGen** (FunReason-MT, 16,978 แถว, 1.0 GB, Apache-2.0): ข้อมูลสุ่มเก็บ "ใน BFCL environment" ตามที่การ์ดเขียนเอง (ไฟล์ `bfcl_multi_turn.json`) จึงปน BFCL multi-turn 🔴 เสียดายเพราะเป็นชุดเดียวที่มีหมวด E (error recovery) จริงจัง

- **allenai/Dolci-Think-SFT-Olmo-Hybrid-Tool-Use-SA:** source เป็น `hotpotqa` ทั้ง 1,595 แถว (100% wiki)
- **rmems/cascading-error-recovery-trajectories, rmems/mcp-tool-schema-drift-trajectories:** การ์ดระบุ `research_only`, `project_training_policy: blocked`
